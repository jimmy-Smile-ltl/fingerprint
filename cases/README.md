# 实际案例 — 理解手册

> 案例的定位是**辅助理解**：每个案例回答三个问题——
> ① 这个反爬在保护什么？② 它的指纹/签名机制长什么样？③ 本工具集能帮上什么忙？
> 每个案例开头都有「💡 一句话理解」，扫一眼就能抓住要点。

## 🏗️ 反爬分层模型

把反爬看成一座六层塔——请求从下往上逐层过关，任何一层被判定为机器，请求就死在那一层：

```
┌───────────────────────────────────────────────────────────┐
│  L6 合规层    技术中立 ≠ 行为合法                            │  ← 案例 19
│         「抓什么、抓多少、用来干什么」决定性质                │
├───────────────────────────────────────────────────────────┤
│  L5 行为层    轨迹像不像人、拼图对不对、验证码过不过           │  ← 案例 09
├───────────────────────────────────────────────────────────┤
│  L4 签名层    请求参数带动态签名/加密体，没有签名=接口不通      │  ← 案例 04/15/16/17/18
├───────────────────────────────────────────────────────────┤
│  L3 环境层    Canvas/WebGL/Audio/字体/时区… 环境像不像浏览器  │  ← 案例 01/06/10/11/12
│              ★ 本工具集的核心战场                            │
├───────────────────────────────────────────────────────────┤
│  L2 挑战层    WAF 下发 JS/验证码，执行对了才放行              │  ← 案例 02/03/07/13/14
├───────────────────────────────────────────────────────────┤
│  L1 传输层    TLS/HTTP2 握手阶段就识别客户端                  │  ← 案例 08
└───────────────────────────────────────────────────────────┘
```

**两个贯穿性认知**：

1. **层与层之间是「且」的关系**——TLS 过了还有 WAF 挑战，挑战过了还有环境校验，
   环境对了签名里还嵌着指纹。失败时要先定位死在哪一层（见现象速查表）。
2. **环境一致性是 L2-L4 的共同命门**——瑞数要补环境、h5st 签名嵌指纹、
   设备 SDK 采集面就是环境。这正是本工具集（采集→补环境→注入→验证）的价值所在。

## 🔎 现象速查表

| 现象 | 大概率死在哪层 | 看哪个案例 |
|------|--------------|-----------|
| 403，headers/cookies 抄得一模一样也没用 | L1 传输 | 08 TLS 指纹 |
| 空响应 / 连接被重置 | L1 传输 | 08 |
| 412 + 一段 JS + 要 cookie | L2 挑战 | 02 瑞数 |
| 405 + 弹出验证码图片 | L2 挑战 | 13 AWS WAF |
| 521 + JS 里 `document.cookie=...` 然后跳转 | L2 挑战 | 14 加速乐 |
| "Just a moment..." / 无感验证 | L2 挑战 | 07 Cloudflare |
| 请求参数里有 `_abck` / `sensor_data` | L2 挑战 | 03 Akamai |
| 返回 `{"code": 37, "message": "请求异常"}` | L3 环境 | 05 BOSS 直聘 |
| 请求体是 `params` + `encSecKey` 两个字段 | L4 签名 | 18 网易云 weapi |
| 请求带 `h5st` / `a_bogus` / `x-s` / `x-zse-96` 类参数 | L4 签名 | 04 / 15 / 16 / 17 |
| 滑块 / 点选验证码，拼对了还是被拒 | L5 行为 | 09 行为轨迹 |
| 换 IP 就好、原 IP 全挂 | L6 风控联动 | 08 的结局 + 19 |

## 🗺️ 阅读路线

按目的选路线，不必按编号顺序读：

**新手路线**（最小闭环 → 工具集）：`17 知乎` → `18 网易云` → `01 注入验证` → `08 TLS`

**指纹主线**（本工具集核心）：`01 注入验证` → `06 设备 SDK 采集面` → `12 字体` → `10 WebRTC` → `11 自动化检测`

## 📖 术语速查

| 术语 | 含义 | 出处案例 |
|------|------|---------|
| JA3/JA4 | TLS 握手指纹：加密套件+扩展的哈希，标识客户端类型 | 08 |
| 补环境 | 在 Node.js 里模拟浏览器 API，让原版 JS 直接运行 | 02/04/15 |
| 纯算 | 完全读懂算法后用 Python 重写，不运行原版 JS | 17/18 |
| JSVMP / 字节码 VM | 把 JS 编译成自定义字节码+解释器，静态阅读极难 | 04/16 |
| 魔改哈希 | 篡改初始常量/轮常量的哈希，标准库算不出相同结果 | 04 |
| 风控联动 | 多个信号综合打分，单点通过也会被整体拒绝 | 03/08 |
| Farbling | 浏览器对指纹注入噪声（每次结果不同）的反指纹技术 | 07/11 |
| sensor_data | Akamai 把环境+行为压缩编码后的提交参数 | 03 |
| 签名族 | 一个站点的签名不是单参数，而是一组配合的参数 | 16 |
| 增量 cookie | `document.cookie` 赋值只更新单个 name，不清空其他 | 14 |
| 挑战-响应 | 服务端下发 JS/谜题，客户端执行正确才放行 | 02/13/14 |

## 案例编写模板

新案例按此结构写，重点是**让读者读完能理解机制、能对照排查**：

```markdown
# 案例 NN：标题

> 💡 一句话理解：用一句话说清这个反爬「在防什么、怎么防」。

> 📖 类型说明（文档型/实战记录型，素材来源）

## 背景
目标站点 / 反爬机制 / 触发现象（出现什么才说明撞上了它）

## 原理（有流程的用 ASCII 流程图）
机制拆解，能用图就不用长段落

## 本工具集的应用
这个案例与本仓库代码的关系（采集/注入/补环境/自检）

## 参考来源（文档型必填）
URL 列表

## 状态
- [x] 已有的部分
- [ ] 待补的部分
```

## 🛠️ 从文档到动手

文档型案例读完之后，想动手时的「第一步」：

| 案例 | 想动手时的第一步 |
|------|----------------|
| 03 Akamai | 用 `test_fp.html` 采集真实环境报告，对比 sensor_data 收集面，先保住「环境一致」这一关 |
