# 案例 13：AWS WAF Bot Control — 405 挑战 + 视觉验证

> 📖 实战记录型案例。素材来自 `多探科技/pro30 aws-waf-token 逆向.md`（真实站点）。
> 与瑞数/Akamai 不同：AWS WAF 的挑战**带视觉验证码**，纯协议过不了，需要图像识别。

## 背景

AWS WAF Bot Control 在判定可疑请求时返回 **405**，要求客户端执行一段 JS：
JS 动态生成**验证码图片**（problem 请求），用户/程序解出后提交 verify 请求，
通过后才放行原请求。

## 挑战流程（实战抓包记录）

```
1. 业务请求 → 405，页面执行 JS
2. problem 请求 → 返回验证码图片（图像在 problem 请求之中）
3. 解验证码（乱点图/图片验证）
4. verify 请求 → 携带 hmac_tag / state / key 参数
   (这些参数来自 problem 请求的响应)
5. 通过后原请求放行
```

关键细节（实战记录）：

- `verify` 的 `hmac_tag` / `state` / `key` 是之前 `problem` 请求下发的
- `metrics` 记录的是时间——从 problem 下发算起约 **60 秒后过期**
- 挑战 JS 本体（gokupros）是 HTML 形式下发

## 与瑞数的区别

| 维度 | 瑞数 | AWS WAF Bot Control |
|------|------|---------------------|
| 挑战形态 | 动态令牌 + VM，无图 | JS + **视觉验证码** |
| 自动化难点 | 环境一致性 | **图像识别** + 时效窗口（60s） |
| 协议侧 | 纯 JS 可复现 | 需 OCR/打码 + 状态机 |

## 本工具集的应用

- 环境指纹部分与瑞数思路一致（`fp_env_patch.js` 补环境执行挑战 JS）
- 验证码图像识别是**另一个问题域**（OCR/打码平台），本仓库不覆盖
- 60 秒时效窗口要求整个「请求 → 解图 → verify」链路自动化串联
