# 案例 9：行为/轨迹指纹 — 「行为即验证」的滑块轨迹攻防

> 💡 一句话理解：拼图拼对了不代表你是人——轨迹「像人的不完美」才是通过的关键，过于平滑反而暴露机器。

> 📖 文档型案例（基于公开资料整理）。极验三代的核心理念就是「行为即验证」——
> 静态指纹之外，**你怎么动鼠标**本身就是指纹。

## 背景

滑块验证码（极验 3/4 代、顶象等）在「拼图正确」之外，还会校验**拖动轨迹是否像人**。
纯协议提交正确位置而轨迹数据机器味过重，一样会被拒。

## 反爬机制

| 环节 | 说明 |
|------|------|
| 轨迹采样 | 拖动过程逐事件记录：时间戳 + 坐标 + 事件类型（mousedown/mousemove/mouseup） |
| 轨迹加密 | 采样序列被压缩/差分编码后并入签名参数（如极验 `w` 参数、顶象对应参数） |
| 行为分析 | 服务端对轨迹做特征分析：速度、加速度、抖动、停顿、回拖、起止平台期 |
| 人机判定 | 「像人的不完美」才算通过——过于平滑的曲线反而是机器特征 |

## 轨迹生成策略（公开资料常见方案）

- **贝塞尔曲线**：分段控制点生成平滑拖动路径
- **五段式**：启动（慢）→ 加速 → 匀速 → 减速 → 末端微调（模拟人对准缺口的过程）
- **差分编码**：相邻点坐标差分存储，减小提交体积
- **噪声注入**：随机抖动、微小停顿，打破机器轨迹的规整性

## 本工具集的应用

行为指纹与静态环境指纹是**互补的两层**，缺一不可：

| 层 | 工具 |
|----|------|
| 静态环境指纹（Canvas/WebGL/时区…） | 本仓库 `all_fp.js` + `fp_env_patch.js` |
| 行为/轨迹指纹 | 轨迹生成器（贝塞尔/五段式/差分编码） |
| 轨迹+环境统一提交 | 签名参数组装（如 `w` 参数） |

判断失败原因时先分清是哪一层：静态指纹对但轨迹被拒 → 修轨迹生成器；
轨迹仿真很好但仍被拒 → 查静态环境与签名参数。
