# 案例 18：网易云音乐 weapi — 经典两段式加密接口

> 💡 一句话理解：请求体 AES + 密钥 RSA 的两段式加密，纯算法可完全用 Python 复现——与补环境无关，是接口加密而非环境校验。

> 📖 实战记录型案例。素材来自 `spider research/其他/pro27 网易云 参数加密`
> （`netease_encrypt.py` + `test_api.py`）。weapi 是「接口加密」类反爬的教科书案例。

## 背景

网易云音乐 Web 端接口不校验复杂 WAF，但请求体经过加密：
明文参数先经 AES 加密放进 `params`，AES 密钥再用 RSA 加密放进 `encSecKey`。
不了解这套结构，接口永远返回错误。

## 加密结构（公开共识）

```
POST 体:
  params    = AES(明文 JSON, 固定密钥)
  encSecKey = RSA(固定密钥, 公钥)

流程:
  明文参数 JSON
    → AES 加密 → params
    → 密钥经 RSA 加密 → encSecKey
  服务端: RSA 解出密钥 → AES 解出明文 → 业务处理
```

- AES 密钥在 JS 中是**明文可见的固定值**（历史版本已广为人知）
- 定位方法：搜索 `encSecKey` / `params` 关键词 → 断点 → 找到加密调用
- 复现简单：`pycryptodome` 实现 AES + RSA 即可，无需补环境

## 与「指纹类」防护的区别

| 维度 | 指纹/环境类（本仓库其他案例） | weapi 类接口加密 |
|------|------------------------------|-----------------|
| 校验对象 | 客户端环境/设备 | 请求体加密结构 |
| 逆向产物 | 环境 + 行为 | 纯算法（可完全 Python 复现） |
| 难度 | 环境一致性是核心 | 定位 + 算法还原，一次性 |

## 本工具集的应用

- 纯算法类接口**不需要**本仓库的补环境——Python 直接算
- 但同站点的 Web 端页面对接时，环境指纹仍可能被校验（两者常共存），
  先分清目标接口属于哪一类再选工具
