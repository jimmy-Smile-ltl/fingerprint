TTL / TLS 现在怎么记录？

TLS 元数据可由 Workers 的边缘 API（TLS / JA3 面板）记录；完整 JA3 需要本地 ClientHello 捕获工具，或 Cloudflare Bot Management（JA3/JA4）。TTL 仍是 IP 包头字段，只能抓包或服务端观测。它们属于 L1 传输层，不是 Canvas/WebGL 的 L3 环境层信号。

边缘观测 / Workers

TLS 连接元数据

浏览器 JavaScript 读不到 TLS 握手。部署到 Cloudflare Workers 后，边缘可以返回本次连接的 TLS 版本、加密套件、HTTP 协议与网络 RTT；JA3/JA4 需要 Bot Management。

本地捕获 / ClientHello

完整 JA3 记录

工具只读取 ClientHello，不完成握手；Chrome、requests、curl_cffi 都能被记录。

python tools/tls_ja3_capture.py --port 8443

另开一个终端触发客户端：

curl -k https://127.0.0.1:8443
python tools/tls_probe.py --impersonate chrome110

对比 requests 与 curl_cffi 的 JA3，可以验证 TLS 指纹伪装是否生效。本工具输出客户端 JA3；JA3S 与 JA4 规则不同。

参考：JA3 指纹介绍（tr0y.wang） · CSDN JA3 文章

文件 fp_env_patch.js 为 all_fp.js 的每一个指纹维度提供了 完整的 Node.js 运行环境。每个浏览器 API 都有对应的模拟实现， 且保持正确的原型链，确保 instanceof 检测和 toString 检测都能通过。

代码中自定义指纹

// 加载补环境（必须在 import all_fp.js 之前）
const { setFingerprintConfig, applyPreset } = require('./fp_env_patch.js');

// 方式 A: 使用预设
applyPreset('macos-chrome');

// 方式 B: 逐项自定义
setFingerprintConfig({
  // --- GPU (决定 WebGL 指纹) ---
  gpuVendor:   'NVIDIA Corporation',
  gpuRenderer: 'GeForce RTX 4090/PCIe/SSE2',

  // --- 硬件 (决定硬件指纹) ---
  hardwareConcurrency: 32,
  deviceMemory: 64,

  // --- Canvas (决定 Canvas 指纹) ---
  canvasSeed: 'my-custom-machine-v1',

  // --- Audio (决定 Audio 指纹) ---
  audioSeed: 0.987654321,

  // --- 时区 (决定时区指纹) ---
  timezone: 'America/New_York',
  timezoneOffset: 300,

  // --- UA/平台 ---
  platform: 'Win32',
  userAgent: 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...',
});

// 然后导入采集函数
const mod = await import('./all_fp.js');

// 现在所有指纹都基于上面的配置生成
console.log('Canvas:',  mod.getCanvasFingerprint().hash);
console.log('WebGL:',   mod.getWebGLFingerprint());
console.log('Audio:',   (await mod.getAudioFingerprint()).hash);
console.log('Fonts:',   mod.getFontFingerprint());
console.log('Hardware:', mod.getHardwareFingerprint());

// 综合指纹
const fp = new mod.BrowserFingerprinter();
const { visitorId } = await fp.getFingerprint();
console.log('Visitor ID:', visitorId);

阶段 1：构建全局骨架（window / document / navigator）

这是所有补环境的基础，必须最先处理。核心原则：

  • window = global（Node.js 全局对象即 window）
  • window.__proto__ = Window.prototype（确保 window instanceof Window 为 true）
  • 清理 Node.js 特有全局变量（GLOBAL、root、__filename）
  • 注入 Node.js 原生对象（Math、Date、JSON、Promise…）
// === 阶段 1 骨架代码 ===
Window = function Window() {};
setNativeTag(Window.prototype, 'Window');       // Symbol.toStringTag = "Window"
window = global;
window.__proto__ = Window.prototype;            // instanceof Window ✅
self = top = parent = window;

// 清理 Node 痕迹
try { delete GLOBAL; } catch(e) {}
try { delete __filename; } catch(e) {}

// 注入必需全局
window.Math = Math;
window.Date = Date;
window.JSON = JSON;
window.parseInt = parseInt;
// ... 其他原生对象

阶段 2：构建构造函数 + 原型链（核心）

阶段 3：逐维度补实现（合成模式 vs 真实数据注入模式）

每个指纹维度支持两种模式：

  • 合成模式（默认）：用 seed 生成固定但独特的指纹值，适合测试、批量生成不同设备指纹
  • 真实数据注入模式：从真实浏览器采集指纹后 原样回放，Node.js 输出与浏览器完全一致

阶段 4：toString 伪装（safeFunction）

很多风控脚本会检测函数 toString() 是否返回 "function xxx() { [native code] }"。如果返回的是真实函数体，说明环境被篡改过。

// === toString 伪装机制（参考 run_js_proto.js / _ab_env_ok.js）===
const _native_toString_symbol = Symbol('function_toString');

// 1. 劫持 Function.prototype.toString
!(function patchToString() {
  const originToString = Function.prototype.toString;
  Object.defineProperty(Function.prototype, 'toString', {
    value: function toString() {
      // 如果函数上有 _native_toString_symbol 标记，返回伪造字符串
      return this[_native_toString_symbol] || originToString.call(this);
    }
  });
})();

// 2. 给任意函数打上 native 标记
function updateFunToString(func) {
  Object.defineProperty(func, _native_toString_symbol, {
    value: `function ${func.name || ''}() { [native code] }`
  });
}

// 3. 使用
updateFunToString(Navigator);
updateFunToString(HTMLCanvasElement);
updateFunToString(Document);
// Navigator.toString() → "function Navigator() { [native code] }" ✅
